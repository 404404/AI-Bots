# ADR-0249：数字员工使用私聊和群聊，而非 Host 会话导航

状态：Accepted（新产品方向；按下面的阶段交付，不代表全部实现）

日期：2026-10-30

范围：仅 `404404/AI-Bots` 的 `standalone/`。不引入 DSH/Cordis，不使用旧 Host。

## 用户反馈与代码事实

用户参考图要求：Bot 是可直接私聊、可加入群聊的数字员工；协作摘要按发生时间进入聊天记录，点击浮层看具体协作；发送键左侧选择模型，模型来源集中在设置。不能继续把单个 Bot 下的多个底层 Conversation 当作主要导航。

当前 `worker-management.ts` 为新员工保存空本地模型配置，通过 `delegation_grants` 引用已有来源；`application.ts` 的私聊仅为主 Bot 解析共享引用。这导致同一员工可以受委派执行，却无法直接私聊。源授权并未缺失，不要求用户重新登录或复制凭据。

## 决策

### 产品对象与权限

- **Bot**：稳定 ID 的数字员工，保存名称、身份、头像和自己的文件记忆。主 Bot 是有显式协调授权的员工，不是所有者或全局管理员。
- **私聊**：用户与一个 Bot 的持续聊天入口。底层 Conversation/Run 继续保留稳定 ID 和历史，不再作为独立侧栏区域。
- **群聊**：独立聊天空间，具有明确成员与发言来源。群成员身份不授予私聊、记忆、模型来源或工具权限。
- **任务**：真实执行链及状态权威。Bot 间协作摘要是已有任务的投影，不另造消息或任务状态；详情从同一持久任务读取。
- **模型来源**：服务端连接及其现有授权的唯一权威。设置负责私密来源和授权；发送区只能选择当前 Bot 已获准使用的连接/模型，不隐式授予权限。

首片复用现有来源 Bot 的加密授权记录及服务端引用；这是兼容存储边界，不把 UI 放到“全局设置”写成已完成独立凭据实体迁移。后续来源实体迁移须另立版本迁移和回退证据。凭据不写入消息、任务快照、DOM、日志或消费者 Bot。

### 第一片：可使用的员工私聊和时间线

1. 统一私聊的连接解析。主与工作 Bot 的选择都必须通过真实授权引用校验；来源撤销、epoch 变化明确拒绝，没有静默回退。自身本地配置作为明确可选来源，不冒充共享授权。
2. 发送区选择器列出该 Bot 获准的连接及支持模型，位于发送键左侧。Codex 模型只来自锁定 SDK 目录；兼容 API 只列已配置模型。选择随新 Run 锁定；幂等重放不得因配置变化或重选而重复执行。

   本地来源须在请求中明确选择，或先通过 `private-chat.select-model` 保存明确选择；没有选择时返回 `model-selection-required`，不为兼容旧可写 CLI 引入隐式本地回退。省略选择的旧调用只保留既有 Run 的幂等重放、明确保存的选择和已有共享引用的授权路径；只读 CLI 不受影响。
3. 新私聊入口把 Bot 绑定到一个持久默认 Conversation。首次选择确定性采用已有最近 Conversation；无历史时创建一次，初始化事务幂等。所有旧 Conversation 保留，可通过同一私聊里的“历史记录”切换阅读/续聊，显示明确的历史上下文；不将 UI 合并显示的历史暗中排除于模型上下文，也不静默合并所有旧线程给模型。
4. 一次选中的私聊上下文仍以真实 Conversation ID 为准，发送和读取一致；换 Bot 或历史记录时丢弃过期异步响应。默认私聊入口与历史选择均使用同一业务命令，刷新/重启不切换到另一上下文。
5. 消息与本次 Conversation 关联的子任务摘要按 `createdAt` 与稳定 ID 排序。员工自己的受委派任务可在明确标为“协作记录”的投影中读取，不伪造成用户私聊。所有结果标明发起者/执行者和来源任务。
6. 摘要只占时间线位置；弹窗展示真实输入、执行者、状态、结果/错误及父子关系。任务更新只更新该摘要，不在输入区固定悬浮。未完成、失败、取消和中断都必须可见。
7. 模型来源及私密登录在全局设置入口管理；移除 Bot 顶部模型标签与独立侧栏“对话”区域。身份、记忆和管理权限继续按 Bot 归属。

### 下一片：真实群聊

群聊必须先有版本化的唯一持久聊天空间、成员和消息归属，再提供创建/加入/移除及发言 UI。用户消息明确选择或 @ 成员；未指定时只允许一个明确的默认响应成员，不能让所有成员无限自动响应。Bot 输出或网页中的 @ 文字不触发新的权限或无限执行。受控委派仍复用 TaskEngine 的预算、层级、循环和取消规则。

每条群消息标明稳定发送者 ID、类型和时间。成员只得到获授权群内的有界上下文及自己的记忆，不得到其他成员私聊或秘密。移除成员须阻止后续请求和迟到发言；成员快照和配置版本可追踪。私聊历史不自动发布到群聊。群聊模型与直接 API/CLI 必须共用相同授权、幂等与持久实现。

## 数据与升级

SQLite 继续唯一保存身份、连接引用、默认私聊指针、Conversation/Run/消息和任务；文件记忆仍按 Bot 独立保存。默认指针不复制消息。时间线是消息/任务的只读投影，弹窗和通知不是第二套数据库。群聊阶段对新实体单独作版本迁移和恢复用例。

使用独立合成数据测试迁移，备份当前候选后再升级。旧镜像读取新 schema 时须拒绝；代码回退和恢复旧数据分别验证。浏览器 worker 未通过严格扫描，仍不晋级；本轮私聊候选应保持浏览器未配置、明确不可用，不以其源码存在声称浏览器交付。
