# Private input separates native credential storage from qualified execution

The #1380 candidate reuses DSH Credentials Service for original values and uses an application-defined owner for PersonaBot/account binding and inline multi-field requests. A reference alone cannot protect a secret from an Agent that can read the native same-user credential file. The candidate therefore qualifies both the trusted CLI and every model-controlled path that could reach its Host, instead of substituting plaintext into an arbitrary Shell command.

One native `CredentialKey` holds one atomic multi-field grant, including the requesting Bot's creation identity and account. Channel history contains declarations and terminal status/references only; live requests belong to the actual Orchestrator Agent and are not restored as waiters. The authenticated Typert invocation peer, rather than a supplied actor label, establishes Owner authority. DSH's Human-only secret authorization prompt is relevant prior art; ordinary question-answer persistence is unsuitable. Its scalar prompt does not supply this multi-field Channel contract, so the candidate renders a BotHarness card while retaining native storage authority.

The only credential consumer is an immutable Node CLI that receives the three selected fields through stdin, performs one GET to the Owner-supplied endpoint, forbids redirects, discards response body/headers/stderr, and returns bounded HTTP status/request success. HTTP success alone does not certify the remote service's authentication. The controlled fixture independently checks the two credentials. The model controls references, never executable text, headers, environment or field substitution in this consumer. Existing execution approval runs before resolution; broad approval never grants another Bot's credential authority.

The Human approved an isolated Linux Execution World with authorized workspace access. Opting into `privateInputExecution` fences the entire dedicated Profile. A scoped application-defined LinuxShell Provider keeps the native `bash` Consumer and approval, launching Docker through the native Subprocess argv seam. It binds the currently authorized canonical root to `/workspace`, translates cwd, rejects overlap with Host Bundle/interpreter/Profile authority and the Host temporary-directory root, permits only the exact Bot Memory subtree within DSH home, protects Git metadata from writes, and preserves foreground exit codes, separate streams, bounded Spill and cancellation. Containers use a digest-pinned Node/Debian image, non-root UID, read-only system, dropped capabilities and no Host credential/environment/socket mount. Normal container network access is available; the controlled service never echoes secrets to unauthenticated requests. Unowned native Sessions retain a stricter unmounted/networkless command world. Other unqualified Host capabilities are refused.

Ordinary configured MCP stdio servers use the native MCP Client Consumer with a controlled Docker argv launcher and the same workspace boundary. The SDK owns stdio spawn independently of Shell/Subprocess Providers and starts disposable protocol-negotiation siblings, so a per-owner label tracks every container for teardown. MCP qualification requires the actual Agent Scope and records only newly installed ToolDefinition identities, excluding global and every ancestor Scope's definitions. Native Registry visibility and an MCP name prefix do not prove execution provenance. Calls recheck exact identity and current workspace authority; a changed generation or revoked root fails closed. Reconnection is disabled for this first qualification. DSH Scope is an external peer module: bundling its unique scope Symbol creates a second global registration plane and breaks concurrent PersonaBots. This is ordinary nonsecret MCP, not reference-consuming MCP (#1384).

The #1380 opt-in boundary was accepted after the Human confirmed the inline interaction and authenticated service result, and the final Standards/Spec reviews and Linux CI passed in [#1391](https://github.com/BotHarness/DeepSeekBot/pull/1391). Windows Host commands, unrestricted Host filesystem tools, background Jobs, Git metadata writes, arbitrary MCP HTTP transports and arbitrary credential-bearing consumers are not qualified. Guest executables come from the pinned image and authorized workspace, not the Host's PATH. A dedicated DSH home is required; older/unfenced Hosts and independently running processes sharing it remain outside this boundary. Stored application grants fail closed if the opt-in is disabled; reverting to an older binary needs the rollback below.

Rejected alternatives are hidden inputs followed by arbitrary-command env injection, exact-value masking, and a second plaintext store in Memory/config/SQLite. None prevents active extraction or preserves the native credential authority. Keeping unrestricted Host tools beside same-user credential storage also fails this boundary. Rotation, revocation and active-use stop remain #1382; concurrent settlement is #1381; Schedule, credential-consuming MCP and IM qualification remain their own slices.

Rollback after storing grants requires purging only application-owned native grants or restoring the isolated pre-trial home before running an older/unfenced binary. Reverting code alone restores a model-readable Host filesystem alongside persistent values. Trusted Owner, Host Plugins, Docker daemon/image and fixed CLI code remain trusted; this candidate does not isolate credentials from those administrators or certify arbitrary third-party consumers. See the [runnable qualification guide](../dev/guides/private-input-cli.md).
