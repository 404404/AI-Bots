# Private account lifecycle qualification (#1382)

This report covers the opt-in local Windows Host with pinned DSH 0.2.0-rc.1 and qualified Linux containers. It does not qualify Linux-server deployment, secret-consuming MCP, Schedule or IM. [ADR-0167](../adr/0167-private-account-versions-fence-consumption-and-revocation.md) records the account boundary and one-way rollback limitation; the [runnable guide](../dev/guides/private-input-cli.md) supplies synthetic-only reproduction.

## Actual PersonaBot results

One real PersonaBot used account `rotation-demo` in its canonical DM. The Owner submitted three private fields in Web Chat, and the existing approval carrier saved a broad tool allowance. The trusted CLI authenticated version A and returned HTTP 200. A blank Owner replacement card accepted B; a later real `ask_secret` returned new references and the CLI returned 200 with no new approval card. Old references were refused before any additional fixture request. During a delayed authenticated call, Owner revocation reported stopped 1, completed 0, uncertain 0; the fixture observed a disconnected connection. Subsequent use was refused. After restarting the exact task-owned Host, the real Bot again received a stable grant refusal, and no fixture request occurred.

A first replacement attempt expired with no references while qualification returned unavailable. Standalone Linux/image qualification succeeded later, and a fresh private request worked. The transient cause remains unconfirmed; this report does not claim it was fixed. The failed request remains in canonical history.

After the review fixes and rebuilt Host restart, independent account `auth-failure-demo` retained its references and returned HTTP 401 while `rotation-demo` remained revoked. Its tool result contained only status and a static private-replacement/remote-authorization repair action. Owner replacement to B then returned HTTP 200 through the real Bot. A second delayed authenticated call was revoked while running: stopped 1, completed 0, uncertain 0, with another disconnected fixture connection. Its revoked references were then refused without another request. A fresh explicit private setup was created for Human review; it does not reactivate either revoked UUID.

The controlled service's final execution counts were requests 7, authenticated 5, completed responses 5, disconnected before response 2, with authenticated versions A/B = 1/4. Two completed responses were the expected 401 cases. An abort and connection closure establish local stop evidence, not cancellation of remote effects or third-party token revocation. Automated tests separately cover successful completion despite abort and a noncooperating consumer's uncertain outcome after the one-second limit.

## Evidence boundaries

[Native Session projection](evidence/1382/native-session-events.json) reads all concatenated native compressed frames and exports only allowlisted sequence/time, tool names, declaration field IDs, opaque references, approval metadata, result status and counts. Owner-created replacement cards have a canonical Channel locator and no fabricated native Session ID. Full prompts, reasoning, commands, HTTP bodies/headers, paths and credential originals remain local. [Qualification summary](evidence/1382/lifecycle-summary.json) records wire/scanner counts and canonical lifecycle projections without raw Chat or credentials.

The actual model-fetch probe compares serialized DeepSeek `/messages` request bytes against raw, encoded and escaped A/B synthetic canaries; it records only byte count and match count. Native Session events, tool output/error results, Chat persistence and logs are scanned independently. Spill scanning reports the number present; zero new Spill files does not establish new Spill-path coverage. The execution projection remains the fixed `http-status-v1` CLI; arbitrary commands never receive plaintext environment variables. The native credential file is the expected original-value authority and is excluded from model-visible surfaces.

## UI and checks

Before screenshots use the exact #1405 base in an independent task-owned Profile; after screenshots use this candidate. Both show SecretRotation, account auth-failure-demo, English and a 1280 × 800 viewport in native light/dark themes. Opaque IDs, times, prior Chat and sidebar roster differ because Profiles are independent. The baseline has no account controls or revocation state. New replacement and revocation states use that prior configured card as their absence-state comparison. Password values are cleared and never restored. T3 captured initial inline controls/replacement/revocation; it later became explicitly unavailable, so the final comparisons used local headless Chromium. Captures are actual rendered Host UI.

The review found and fixed startup cleanup racing Owner mutation, configured publication before failed account activation, missing structured stop diagnostics, and duplicate-tab terminal-state reconciliation. Account activation now precedes configured publication; both proofs fence consumption. Focused red/green tests verify empty-reference failure, queued cancellation, revision races, post-commit native response failure, startup recovery, stale polls, peer authority and safe 401 output. The two-axis review found no remaining code-level Spec issue; repeated grant validation remains a possible duplication smell, not a documented violation.

Local lint, format, typecheck and build passed. The Windows full-suite attempt was stopped after widespread cleanup failures and timeouts; an isolated unchanged registry test reproduced EPERM in recursive temporary-directory cleanup. This is an incomplete full-suite result, not a pass. Linux CI and final Human review are reported separately on the PR. No production service, external mail or second production IM receiver was started.
