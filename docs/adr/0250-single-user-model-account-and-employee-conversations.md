# ADR-0250：单用户模型账户与员工对话

状态：Accepted（独立产品方向；各项以对应验收为准，本文不是已实现声明）

日期：2026-10-31；范围仅 `404404/AI-Bots` 的 `standalone/`。本决定调整 ADR-0244、0245、0247 和 0249 中逐 Bot 模型连接、模型创建员工及主要身份自动指定的部分；原 DSH 插件不改。

## 问题和现状

现有 schema 8 将模型配置和加密授权挂在 Bot 上，以显式连接引用和委派授权连接主 Bot 与工作 Bot。用户需要配置多处，界面暴露“主 Bot”“Bot 管理目录”和授权委派开关；模型可以在开关允许时创建或修改工作 Bot。群聊没有持久空间或执行路径。当前 GK50 只读统计有 15 个 Bot、1 条 OAuth 授权、3 份 Codex 模型配置；数量不证明这些配置完全相同，也不暴露凭据。

## 决定

- 模型账户属于单一用户和产品实例：设置一次来源、凭据、模型及显式代理，所有私聊、群聊和委派执行使用同一服务端授权。聊天发送区可选择该账户可用模型；模型输出和页面内容不能更改账户、导出凭据或授予外部工具权限。授权撤销或更新时，在途执行须重新检查并明确失败，不静默直连或切换账户。
- 升级时只在唯一有效旧来源可无歧义确定时自动采用该来源；多个可用旧授权或冲突无法安全判断时保留所有旧记录并要求用户在设置中明确选择，不复制或丢弃它们。只在独立副本测试并备份；迁移与回退包括授权、Bot、历史、记忆、任务和稳定 ID。不存在授权时不阻止创建员工或阅读历史，发送给出明确状态。
- 员工只能由用户通过页面或同一认证 API/CLI 创建和定义。模型工具、对话文本、任务输出和旧的策略开关都不能创建或修改员工，也不能提升授权。按名称生成的角色是建议，用户可修改；新员工创建后在自己的私聊中主动询问用户希望其承担什么工作。模型不可用或分析失败时仍发送明确标识为预设欢迎语的询问，同时显示角色建议待完成并保留重试入口；不能把预设文字冒充模型分析。创建和首次问候必须幂等，持久化、可恢复且不泄露其他员工的私聊或记忆。
- 零员工时提供创建入口；只有一个时该员工自动承担主要联系职责。多个员工时由用户明确选定主要联系人，选择可更改、持久且不依赖名称、角色提示或模型自称；现有多个员工升级时询问用户，不静默把历史自动创建的 singleton 当作用户选择。日常界面不出现“主 Bot”或“Bot 管理目录”，选择时用易理解的“主要联系人”等措辞。未选择时允许逐员工私聊和群聊，协调功能明确提示先选择。
- 用户可向主要联系人直接提出委派，也允许其在完成任务分析后将工作交给已有员工；不要求用户预先在设置中逐个授予委派开关。服务端仍按发起任务和已存在目标的稳定 ID、最大深度、循环、并发、超时、取消及幂等约束执行；委派输入明确且有界，只带目标员工自己的记忆，不提供其他员工的私聊、记忆或凭据。协调者不能通过委派创造员工或更改其身份。
- 群聊有自己的持久空间、稳定 ID、成员、用户和 Bot 消息、时间戳与执行状态。用户明确 @ 或选择响应员工；未指定时使用用户明确指定的默认回复员工，否则提示选择。一个用户消息可让多个明确选择的成员依次真实发言，但单次执行和自动唤醒有界；Bot 输出中的指令或 @ 文本不能自行启动更多对话。请求仅携带该群有界历史及执行者自己的记忆，成员变更后重新检查并阻止被移除员工迟到发言。群历史不可访问私聊或其他群。
- Web、CLI、API 和模型工具通过同一服务端业务与权限检查。SQLite 是唯一结构化持久权威；有版本的迁移失败即停止，旧 schema 需要独立数据备份恢复，代码回退不是数据回退。继续使用独立 Node 后台，不调用旧 DSH Host，也不建立无认证公网 API。

## 分阶段验收

先实现共享账户、用户创建和明确主要联系人，接通现有私聊与委派；再交付包含真实发送和回复的群聊纵切，扩展多员工发言、恢复和边界。名称分析须通过实际模型执行、持久历史和用户可见结果共同证明；无模型时的预设欢迎语必须明确标识，不能当作模型证据。每片由主代理先写[验收用例](../acceptance/standalone-single-user-employee-cases-2026-10-31.md)，GPT 6 Luna 编码，GPT 6.1 Terra 独立验收；真实 LAN、真实模型、模拟服务、迁移和页面证据分别记录。当前 20443 保持对照，独立数据和空闲端口验收后才按固定 digest 升级。
