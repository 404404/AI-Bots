# 记忆演化

打开 **Bot 私聊 → Channel sidebar → 记忆演化**。这里将当前未提交改动与 Git 历史分开。查看差异不会应用差异，也不会回退文件。

## 检查一次变更

1. 展开 **记忆演化**。
2. 在 **当前记忆** 中展开变更分组，点击文件，在中间区域查看 **未提交差异**。
3. 在 **提交历史** 中点击提交行，查看改动文件和 **提交差异**。
4. 查看后点击 **返回对话**。需要更早的历史时，点击 **加载更多提交**。

![记忆仓库的分支、提交历史与中间区域的提交差异](/guides/channel-sidebar/03-memory-evolution-zh.webp)

| 控件或标签                 | 含义                                                               |
| -------------------------- | ------------------------------------------------------------------ |
| 新记忆 / 已有记忆的更新    | 用更接近记忆用途的方式分组未提交改动。                             |
| 未暂存 / 已暂存 / 未跟踪   | 显示术语切为 **Git** 时，按对应 Git 状态分组。                     |
| HEAD 与分支标签            | Git 图中的当前提交与分支引用。                                     |
| 已记录 / Git 提交 / 待修复 | BotHarness 对 Git 历史的检查点标记，不代表文件作者或对内容的批准。 |

点击 **记忆演化** 标题右侧的齿轮，在 **显示术语** 下切换。它只改变标签与分组，不改仓库内容。

## 请求切换分支

在 **搜索分支** 中选择已有分支，再点击 **切换**。界面会向这个 Bot 的 Orchestrator 发送请求；只选下拉项不会检出分支。等待 Bot 报告结果，再核对显示的分支与当前文件。Git 因未完成改动而拒绝时，应保留改动，查看 Bot 的说明。

在提交差异中，**从该记忆节点新建并切换分支** 会打开新分支名称输入框。**创建并切换** 同样发送 Bot 请求；它从所选提交创建分支，不会撤销原分支上的后续提交。Bot 完成后，再核对操作结果和文件。

## 恢复到更早的记忆

在 Git 图里选中一个提交，该提交的方块里会出现 **恢复到这次提交**；也可以右键任意提交。确认提示会说明：记忆会恢复成这次提交完成后的样子，包含这次提交的改动，不包含之后的提交。如果记忆里有还没提交的改动，会先自动把它们存成 Git 图里的一个普通提交；你也可以顺手给恢复前的版本起个名字。点击 **保存改动并恢复**（没有未提交改动时是 **恢复**）后，再新增一个提交，让文件回到所选提交的样子。所有能回去的点都在同一张 Git 图里；恢复完成后，**记忆文件** 会立即刷新。

## 给版本起名

选中任意提交，点击 **给这个版本起名**，写一个以后一眼能认出的名字，比如「整理前的草稿」。名字会作为标签显示在 Git 图里这个提交上；在提交方块里点名字旁的 × 可以移除。名字用 Git tag 保存，跟着记忆仓库走，不会改动任何提交。

这一栏的标题是 **记忆**，旁边有两个标签：**演化** 显示 Git 图，**版本** 只列出你起过名的版本，最新的在上面，不管隔了多少提交都能直接找到。点一个版本可以查看它的改动，再选择 **恢复到这个版本** 或 **移除名称**。

## 高级：系统快照

**高级 · 系统快照** 列出 BotHarness 在记忆变化、Bot 会话结束时自动拍下的快照。每个快照用隐藏的 Git 对象保存分支、提交、暂存区和未提交文件，不出现在 Git 图里，作为最后一道保险；平时回到过去请直接用 Git 图。选中快照后点击 **复制并恢复** 即可回到那时；操作前会完整备份仓库，并显示备份位置。**修复记忆** 状态有独立的确认与备份流程。
