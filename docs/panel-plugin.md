# VRM Panel: first runnable slice

Room iteration 3 is implemented and isolated-Host verified; Human visual acceptance is pending. See [the handoff](qa/2222-vrm-materials-handoff.md) for the current validation boundary.

This is the implementation guide for [T1 #2222](https://github.com/BotHarness/DeepSeekBot/issues/2222), under [ADR-0234](adr/0234-panels-are-native-plugins-with-independent-binding.md). It does not implement the T2 Task Kanban or the later migration tickets. Human acceptance remains the gate before expanding those slices.

## Install and open

Build the repository with the pinned dependencies, then install the independent native Bundle into an isolated DSH Profile:

```sh
pnpm install
pnpm build
dsh plugin --profile web-dev add "link:<absolute-checkout>/packages/vrm-companion"
```

Use the worktree's pinned DSH CLI and the same DSH_HOME as the running Host. The package has its own manifest, Patch, Host entry and Client entry. The Host entry creates no domain state or worker. It is not included automatically in the DeepSeekBot umbrella. Native bundle activation/deactivation remains DSH-owned. The isolated CLI install/remove path was verified with a Host restart after each Profile mutation; changing the package manifest alone is not proof that a running Host has unloaded it.

In Bot mode, select a Bot DM, open Messages if it is closed, then choose **VRM Companion** in the Messages header. Group Channels have no contextual character entry. **Pin character globally** in the Panel header's **Scene** menu creates a separately identified, fixed-Bot instance whose title names that Bot. Close/reopen preserves the binding and layout; **Delete instance** in the same menu removes its metadata. Refresh restores fixed instances even before a Channel is selected. Uninstalling the plugin retains dormant instance metadata for reinstall. A missing/deleted Bot produces an unavailable state.

## Public Client contract

Plugin authors import only types from `@botharness/ui/panels` and inject the application-defined `dockPanels` and `botPresentation` Services. DSH/Cordis still owns Plugin/Fiber disposal and Service injection. These are BotHarness contracts, not native DSH Panel or Activity APIs.

```tsx
import type { Context } from '@deepseek-ai/cordis';
import type { DockPanelProps, PanelServices } from '@botharness/ui/panels';

export const inject = ['dockPanels', 'botPresentation'];
export function apply(ctx: Context & PanelServices) {
  function View({ channel, botId }: DockPanelProps) {
    const binding = botId ?? channel?.botSlug;
    return <div>{binding}</div>;
  }
  ctx.effect(() =>
    ctx.dockPanels.register({
      id: 'my-character',
      title: 'My character',
      scope: 'channel',
      binding: 'current-bot',
      component: View,
      headerAction: ({ channel, botId }: DockPanelProps) => <button>Options</button>,
    }),
  );
}
```

The optional `headerAction` renders in the Panel's native header, beside its title, with the same props as the body; a fixed instance's header receives that instance's `botId` and `instanceId`. Put a Panel's controls there rather than over its content. The complete resource-owning example is `packages/vrm-companion/src/client/index.tsx`. Acquire `botPresentation.acquire(botId)` when a view mounts; use `getSnapshot` and `subscribe`, and call its idempotent `dispose` when it unmounts. Do not acquire resources during React rendering. Subscribers may return a Promise; one failed subscriber is isolated with bounded diagnostics.

A snapshot contains the current Bot name, availability, paused state, connection state, Activity, optional attention, current visible text, speaking flag and mouth weight. Activity is read from the existing ClientStore projection; the presentation Service does not write Activity or own execution. Attention is independent of Activity: waiting alone does not imply a Human response is required.

There is one output clock and one authorized output subscription per Bot per Client. Multiple views share that clock but own independent Three.js scenes, skeletons, expressions, cameras and renderers. Closing the last view releases the output stream and timer. Different Bots have different output clocks. This slice consumes only committed output from that Bot's own DM; it does not expose shared/private group contents, model deltas or hidden reasoning.

## Persistence and failures

Ordinary instance metadata extends the existing version-8 layout document, with no second persistence key or Host store. Metadata contains instance ID, definition ID, fixed Bot ID and display label; at most 16 ordinary instances are retained. Contextual open state and split geometry remain in the existing per-Channel layout owner. Unknown valid split leaves survive plugin reload.

Registration and instance operations throw stable refusal strings: `invalid_panel_definition`, `panel_definition_unavailable`, `invalid_bot_binding`, `panel_instance_limit`, `panel_layout_unavailable`. An unavailable definition cannot create an instance. A failed save leaves the prior instances intact. Disposers are idempotent and cannot unregister a later replacement.

Mounting or reconnecting establishes a fresh output checkpoint; it never speaks baseline/history. Disconnect, hidden document, pause, deletion and final disposal cancel the current output. Deduplication uses connection generation, Channel and message identity, not text equality. Queues and deduplication sets are bounded. The first slice is silent: it does not opt into the old floating companion's audio owner or add TTS.

## Rendering and assets

The canvas fills the Panel body. The Panel header shows the Bot's current state and a **Scene** menu with every control; only committed speech, attention, loading and errors overlay the scene. There is no separate expanded view: widen the scene by resizing the native chat/Panel split. Camera, room-time and shading choices survive a remount of the same Bot's view during the page session; they are presentation preferences, not durable state. Loading shows a transient status without a retry action; only a failed load or lost WebGL context offers **Retry character**.

The default pose sits at a desk with hands aligned to the keyboard. The **Scene** menu groups Character (change character, default, MToon/lilToon), View, Time, Weather, Look and Movement, and exposes Desk/Room/Portrait views and Reset view, **Auto camera tour**, Sit down, Stand up, and opt-in Walk around. **Auto camera tour** cycles the camera through desk, portrait, wide, over-the-shoulder and room shots: it holds each shot for 12 seconds with a slow drift, glides to the next over 3 seconds (cuts under reduced motion), pauses for 20 seconds when the viewer drags the camera, and stops when a view is picked. Walking stays in a bounded lane and yields to real work or speaking; Sit down cancels wandering and returns to the chair. Each view owns its choreography, with no Host mutation or persistent world simulation. While the Bot is idle and the character is seated, it occasionally makes a small decorative gesture: looking toward the window, stretching, resting its chin on a hand, sipping from the cup or glancing at the viewer. A gesture starts after a random 6–14 seconds of eligible idle time, never repeats the previous one, and eases back to the keyboard as soon as the Bot starts working, speaks or the character is asked to move. Time spent not idle, hidden or under reduced motion does not accumulate, so returning never replays missed gestures. Each view schedules its own gestures; they carry no task or emotion meaning. The sip uses a grip declared on the mug (wrist point, hand orientation and finger curl): the arm reaches it with IK and the mug follows a planned path to the mouth, so moving the mug does not require new animation. Reduced motion suppresses wandering and ambient motion and resolves requested poses directly.

The room, furniture and exterior are self-authored Three.js geometry plus seven CC0 KayKit models (books, a decorated shelf, two cacti, a picture frame, a pillow and a single book). Room objects use real-world sizes (a 27-inch monitor, a tenkeyless keyboard, an 8 cm mug, an articulated desk lamp) in a low-poly style: few segments and matte colors drawn with a smooth four-step toon shader, including the KayKit models, with a soft painted brush texture across surfaces. The lamp is a spotlight that casts a warm pool on the desk, and night shifts the ambient light to blue. The desk view follows the composition of the lo-fi study game Chill with You: the camera sits beside the desk at the character's front, the monitor stands in front of the character angled toward the camera, the desk lamp leans over it, a row of books and the mug sit between them, and the window with the penguin plush and boombox fills the background. The desk is L-shaped: a side wing along the left wall holds the book hutch, a spinning turntable with leaning record sleeves, an open laptop, a small speaker, and above it a wall shelf and a corkboard with photos and notes. A pothos hangs at the window and sways, a firefly jar on the window seat glows at night, three small prints hang right of the window, a desk calendar shows today's date, and book spines carry labels. The room is furnished like a lived-in study corner: a desk hutch with books, a reed diffuser and a sprout, a pen cup, phone, notebooks, a coaster and a succulent on the desk, a drawer cabinet, a rug, baseboards, a star-chart poster, a wall clock that shows local time, a floor lamp, string lights across the window, and a candle, books, a pillow, cacti and a picture frame on the window seat. An open book on the desk turns a page every few seconds, loose sheets lift in the breeze from the window, and dust drifts in the daylight. The floor lamp, string lights and candle brighten as the room darkens. Several zoned lights add to the desk lamp: a wall sconce on the left wall, a warm glow inside the book hutch, an LED strip under the wall shelf, and at sunset a warm bounce from the window with soft sunbeams. Cables run from the lamp and monitor to a wall outlet, an air conditioner sways its louver above the wing, and a basket of blankets, slippers, a floor cushion and a printed mug fill out the room. While typing, the character rests its hands on the keys and strikes them with individual fingers in uneven bursts; head turns, glances and idle gestures ease in and out. When the Bot speaks, the text appears in a speech bubble above the character's head, styled like the Bot avatar's bubble, and its tail follows the head as the camera moves. A framed window opening in a plaster back wall, with linen curtains, reveals soft shader-drawn cloud layers, balloons, a glowing sun/moon and stars; the same local wall clock drives sky colors and the sun's lighting direction. **Local time** is the default; **Sunset** and **Night** are explicit lighting previews. At night the room light drops and the desk lamp becomes the main warm light. **Clear** and **Rain** in the Scene menu switch the weather: rain brings streaks outside, an overcast sky, dimmer sunlight and droplets running down the glass. Clouds are drawn as soft, misty shapes lit from the sun's or moon's direction, the sun has a ringed halo, and birds occasionally cross the sky. **Lo-fi look** (default) adds a screen pass in the style of Chill with You: dark outlines where objects overlap, a soft glow around bright lights, a halftone dot texture in the shadows, a warm red grade and haze at sunset, a cool blue-teal grade at night, and a vignette; **Plain** draws the scene without it. The monitor shows what the Bot is doing: code being typed while working, a scrolling log while thinking, a dialog while waiting or blocked, and a music player with the local time at idle or while the character is away from the desk; at night its glow spills colored light onto the desk and the character. **Change character…** in the **Scene** menu loads a `.vrm` from the viewer's computer in place of the default character. The file is kept in this browser's IndexedDB for that Bot, so it survives reloads, and is never uploaded; if the browser refuses to store it, it stays for the page session and the panel says so. **Use default** switches back and forgets the file. VRM 0.x models such as VRoid exports and VRM 1.0 models share the same choreography: poses use the standard humanoid bones, the model is scaled to the same seated height, the hand IK uses each model's own arm lengths, and only expressions the model provides are used. The headphones are only added to the default character. The character gets a rim light that follows the time of day (warm at sunset, cool blue at night), and the desk lamp lights the desk in front of the keyboard rather than the hands. **MToon** (default) and **lilToon** are a reversible shading comparison; the lilToon port uses only the first directional light, so the desk lamp does not light the character in that mode. Clouds, rain, leaves, steam, paper, the screen and dust move while visible; hidden views stop frame work and resample current local time on return. The room is a bounded T1 presentation, without weather services, music, timers, room editing or a second durable authority.

The renderer uses `three@0.180.0` and `@pixiv/three-vrm@3.5.5`. Idle/thinking/working/waiting/blocked drive normalized humanoid poses; a separate text clock drives the mouth and limited speaking gestures, so working and speaking can coexist. Each Activity also maps to a blend of the model's own facial expressions (relaxed at idle, a thoughtful look upward when thinking, focused brows when working, an expectant smile when waiting, a troubled look when blocked); speaking opens the eyes and adds warmth except when blocked. Expressions ease in and out, expressions the model lacks stay at zero, and a view that is not live returns to a neutral face. This is presentation only: it does not add an emotion fact or Host state. Reduced motion suppresses repetitive movement. Hidden/zero-sized panels stop drawing; restoration resets the frame delta. Failed loads and WebGL context loss leave readable state/text with a retry action. Disposal releases observers, animation frames, geometry/materials/textures, ImageBitmaps and the renderer, including a model that finishes loading after close.

The bundled default character is VRoid Project's AvatarSample_A (VRM 0.x), whose VRoid Hub conditions allow redistribution and modification without credit; it ships with its textures downscaled and is not under the repository's source license. See [asset provenance and permissions](../packages/vrm-companion/assets/README.md). It is not the final character art direction or a claim to reproduce Nintendo assets. No model upload, VRMA library, wardrobe, scene editor or TTS settings are included.

For this local slice, the sample is embedded in the Client bundle to avoid inventing an asset-serving route. The resulting Client is about 16 MB before transport compression, and each instance owns its mutable GPU resources. Measure cold loading and multiple instances on the target machine; this is an explicit initial-size limitation, not a performance target.
