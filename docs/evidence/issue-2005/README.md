# IM DM command verification

PR [#2010](https://github.com/BotHarness/DeepSeekBot/pull/2010), issue [#2005](https://github.com/BotHarness/DeepSeekBot/issues/2005). Qualification date: 2026-10-18. Runtime: the worktree-pinned DSH `0.2.1-rc.2` in a fresh isolated Profile.

The production Plugin handled six text commands through a controlled application-defined Weixin Provider: Chinese help, status, model customization, effort reset, idle stop and fresh Session. Each reply committed an accepted canonical Outbox intent and attempt, each command Admission completed without an error, and the commands created no model work. `/new` archived the real native Orchestrator that existed before the check; ownership retained its history and no current Session remained. Re-delivering the model command changed neither its plan revision nor its Outbox count. The online `bot-new-session` CLI also returned `{"started":true}` against the same live Host. The saved Model Plan contained only an Orchestrator override, preserving Assignment inheritance.

Automated checks covered the reported group-message regression, attachment and unavailable-service fallthrough, concurrent command ordering, revocation before execution and during lookup/validation, answer-only capability refusal, Session rollback, CLI busy refusal, reply deduplication, unknown Outbox results and long response chunking. The related nine-file suite passed 276 tests; after the attachment fallthrough case was added, the final intake suite passed eight tests. Independent final review found no remaining Standards or Spec blockers.

This is controlled-Provider and native Host/CLI evidence, **not native WeChat delivery or rendering**. No paired-owner receiver window was assigned for this task. A native model follow-up attempt returned `GoUsageLimitError` (429), so it does not qualify a successful model reply. The first browser helper timed out on an outdated visible-Settings precondition; the saved failure had no console errors, and a subsequent accessible-name drive dismissed Preview Notice and opened the real Bot mode with a clean console. Linux CI separately verifies the full docs wrapper; the local Windows wrapper hit its existing `spawnSync pnpm ENOENT` in slide generation.
