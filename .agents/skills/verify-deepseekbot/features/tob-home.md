# Home and the protected Tob DM

## Grants, approval and connector policies (#2094)

Use a task-owned isolated Web Profile and synthetic Bot/Workspace. Do not launch native Desktop in parallel; the parent/shared-device owner schedules that proof. The same existing owners must be read independently through authenticated Human CLI after each Tob operation.

1. Seed an ordinary Bot and a real disposable Workspace through Human `create` and `workspace-create`; these are preconditions, not Tob proof. Record its exact Bot id, Workspace id, grants, `access`, selected Approval Template and `failure-alerts` state.
2. In Home ask Tob naturally to authorize that Workspace for the selected Bot. Require an ordinary native bash/pwsh call of `deepseekbot grants` followed by `grant-create --workspace ... --expected-state ...`, a rendered fresh Human approval with previous state/target/patch, and canonical grant readback. Open that Bot's Workspace/access UI and verify the same directory and capability. Request revocation, review it, and verify the canonical grant is revoked and subsequent use refuses.
3. Ask Tob to select the built-in Cautious Approval Template for the synthetic Bot. First deny the management approval and require `approval-denied` with unchanged selection. Ask again, approve once, require CLI template discovery and `approval-template-set` with the observed fingerprint, and read the selected template in the existing Bot UI and Human CLI. Full access or an automatic template cannot replace this Human decision.
4. Ask Tob to disable failure alerts for that Bot. Review the exact existing connector setting, approve once and require `failure-alerts-set` through native Shell. Read the same failure-alert owner through Human CLI and the rendered messaging settings. No test/retry/external message is needed or authorized by this local policy check.
5. Leave one policy review pending, change its canonical state independently through Human CLI, then accept the old review. Require `stale-policy`, unchanged independently edited state and a real Tob reply. Record source revocation and asynchronous Workspace status races separately in source tests; do not call these runtime-proven from screenshots.

Keep screenshots of each approval and visible resulting setting, accessible trees, browser console, fresh native Tool trace ids, handled Human delivery, completed turn and actual reply, plus exact canonical readbacks. On the same Profile after an externally scheduled Host restart, reopen the affected UI and compare saved state. Repeat on actual macOS Desktop separately before claiming that gate. Preserve first failures, and disclose any skipped branch.

For IM setup, use a qualified disposable Provider configuration and record its exact availability. Naturally request a start from Home, review it, and require `im-authorize` through native Shell with no QR/native attempt id in the Tool Result. Open Applications, find the matching pending platform/expiry row, select Continue setup and a synthetic Bot, and require the existing private setup form. Correlate the Human-only resume lookup with native `setup.poll` for that exact attempt and prove no additional `setup.start`. Credential submission or Human scanning remains a separate authorized step; a visible private form alone does not prove native account provisioning or external delivery. Ask Tob to poll its opaque receipt, then review cancellation with the current state fingerprint; also retain unknown/foreign receipt, stale cancel and unavailable Provider outcomes. `im-setup-receipts`/`im-setup-resume` are independent authenticated Human CLI checks and must be denied in scoped Tob context. Credential/token/verification stdin and OS/browser consent remain existing Human flows. Do not label unavailable Provider state, OS permission required or skipped external delivery as success.

## Sub-features

- Home is a global panel. Fresh workspace entry opens it; upgrades append its control without opening it or replacing existing geometry.
- Tob is one protected local identity with canonical Memory, Workspace and Human DM. Re-entry does not repeat its welcome.
- Model setup replaces the Home input when unavailable, returns to it after native configuration and never auto-sends.
- Home sends once through the existing Human DM path; the conversation continues in Messages.
- Tob uses native Shell to discover and invoke the DSB CLI. Scoped management covers default and per-Bot models, presets (create/read/update/apply), four native runtime fields, telemetry, Git availability/install and release operations through existing owners and review; the former dedicated management tools are absent.
- CLI management is authorized only for the protected Tob root Orchestrator and its current accepted Human DM. Shell authority expires when that execution finishes; other Bots, delegation, revoked sources and direct runners cannot borrow it.
- Old nested layouts and custom/disabled shortcuts remain preserved.

## How to get to it (user POV)

Enter Bot mode, then Home in the control rail. Configure a model if prompted. Ask Tob for the current Assignment concurrency limit; request a change and inspect its approval before accepting or denying. Open shortcut settings to customize Home. Move/resize Home and Tob child panels, close/reopen them and restart.

After an approved write, restart the same isolated Host/Profile and read native Settings again to prove durability. Repeat read, approve, deny and stale through the actual macOS Desktop and save its own evidence; a Web renderer result does not qualify Desktop. ## Gotchas

- AX launch model overrides intentionally make native default-model settings read-only. Model-setup QA must use an isolated launch without that command-line override; never edit shared credentials to make the test pass.
- The test service may return quota exhaustion even when readiness reports a valid route. Keep that first failure; changing to an authorized available provider is a new attempt.
- Accessible labels are localized. Inspect the saved tree before treating a selector timeout as a product failure.
- Management CLI requests refuse without original Human-DM provenance. Do not add a Human Host token, explicit Host override or direct-runner exception to make a Bot request pass.
