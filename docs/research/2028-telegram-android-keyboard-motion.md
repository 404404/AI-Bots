# Telegram Android keyboard motion: source findings for #2028

Researched 2026-10-17. Scope: Telegram's Android chat composer, system IME, and app-owned emoji/bot panels; comparison with BotHarness's installed `react-native-keyboard-controller` 1.21.9. Source inspection only; no phone, service, or application-code changes.

## Result

Telegram does not establish one universal “250 ms Telegram keyboard” setting. Its current chat has a hybrid of platform animated insets and its own 250 ms content/panel animator. The system keyboard is requested through Android's input-method service. Changing the composer's easing alone does not change the system IME's motion and can separate their edges. Preserve the present direct keyboard-following path until a same-device recording establishes whether the complaint concerns IME motion, composer lag, or content relayout.

## Telegram: the active modern path

`LaunchActivity` installs a root `WindowAnimatedInsetsProvider`. `ChatActivity` subscribes its `WindowInsetsStateHolder` to that provider, connects the state holder to `ChatInputViewsContainer`, and supplies the in-app controller to `ChatActivityEnterView`. The provider forwards frame-by-frame IME insets from `WindowInsetsAnimationCompat.onProgress`; it does not supply its own duration or interpolator to the system. [Root installation](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/LaunchActivity.java#L460-L464), [chat subscription](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/ChatActivity.java#L9018-L9023), [input provider](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/ChatActivity.java#L4642), [in-app controller](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/ChatActivity.java#L8099), [animation forwarding](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/Components/inset/WindowAnimatedInsetsProvider.java#L27-L47).

This is **hybrid**, not exclusively the platform curve. The state holder also animates endpoint inset changes with `FactorAnimator` using `AdjustPanLayoutHelper.keyboardInterpolator` and `keyboardDuration`. During active platform animations its getters return `max(actual animated IME inset, own animated inset)`; after the platform animation it reconciles without another animation. Therefore the visible composer can follow the larger of two trajectories. This is observable source behavior, not evidence that copying the blend would improve our device. [Local animator](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/Components/inset/WindowInsetsStateHolder.java#L28-L58), [endpoint animation](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/Components/inset/WindowInsetsStateHolder.java#L93-L146), [combined getters](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/Components/inset/WindowInsetsStateHolder.java#L176-L201), [actual frame/end handling](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/Components/inset/WindowInsetsStateHolder.java#L278-L300).

The input container reads those getters and positions its composer bubble using `translationY = -maxBottomInset - bottomGap`. Its in-app panel uses the animated IME/in-app height. This is native view placement tied to the shared inset state. [Inset reads](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/Components/chat/ChatInputViewsContainer.java#L154-L166), [view positioning](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/Components/chat/ChatInputViewsContainer.java#L184-L200).

## What the constants actually animate

| Mechanism                         | Timing / curve                                                                                 | Ownership and applicability                                                                                 |
| --------------------------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `AdjustPanLayoutHelper` fallback  | 250 ms; `ChatListItemAnimator.DEFAULT_INTERPOLATOR`                                            | Animates application view heights/translations after height changes; does not set the IME window's timing.  |
| Exact keyboard interpolator       | Cubic Bézier `(0.19919472913616398, 0.010644531250000006, 0.27920937042459737, 0.91025390625)` | Shared by the fallback and modern state-holder animator.                                                    |
| `CubicBezierInterpolator.DEFAULT` | `(0.25, 0.1, 0.25, 1)`                                                                         | A different generic constant; substituting it as “Telegram's keyboard curve” is incorrect at this revision. |
| Emoji/bot-panel animation         | Uses the same keyboard duration/interpolator                                                   | App-owned popup motion, including cases when the system keyboard is absent.                                 |

Sources: [helper constants](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/ActionBar/AdjustPanLayoutHelper.java#L39-L44), [fallback start](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/ActionBar/AdjustPanLayoutHelper.java#L127-L166), [view translation](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/ActionBar/AdjustPanLayoutHelper.java#L192-L230), [exact curve](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/recyclerview/ChatListItemAnimator.java#L47), [generic default](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/Components/CubicBezierInterpolator.java#L11-L16), [popup animation and in-app height request](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/Components/ChatActivityEnterView.java#L12748-L12782).

The legacy helper contains an optional Android 11+ callback using `getInterpolatedFraction()`, but its static default switch is `false`; that callback additionally refuses to take over below 90 Hz. Do not describe it as Telegram's unconditional modern path. The newer provider above is separately installed. Legacy keyboard-height measurement uses visible-window bounds and posts size-change notifications; it is not a source of native per-frame IME progress. [Optional callback](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/ActionBar/AdjustPanLayoutHelper.java#L408-L448), [installation gate](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/ActionBar/AdjustPanLayoutHelper.java#L299-L301), [height measurement](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/ui/Components/SizeNotifierFrameLayout.java#L470-L498).

## IME control, Android versions, and accessibility

Telegram's inspected ordinary show/hide helpers call `InputMethodManager.showSoftInput` / `hideSoftInputFromWindow`; they pass no duration or easing. [Show](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/messenger/AndroidUtilities.java#L2496-L2506), [hide](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/org/telegram/messenger/AndroidUtilities.java#L2559-L2567).

Android 11/API 30 introduced native synchronization with IME animation. API 29 and earlier require compatibility behavior and cannot be assumed to expose the same system trajectory. Android also offers explicit API 30+ `controlWindowInsetsAnimation` to drive system windows frame by frame, which is a separate ownership mechanism from observing insets. Its duration/interpolator parameters describe an application-controlled animation; changing a React view's easing is not equivalent. [Android synchronization guide](https://developer.android.com/develop/ui/views/layout/sw-keyboard#synchronize-animation), [control API](<https://developer.android.com/reference/android/view/WindowInsetsController#controlWindowInsetsAnimation(int,long,android.view.animation.Interpolator,android.os.CancellationSignal,android.view.WindowInsetsAnimationControlListener)>).

Telegram's `FactorAnimator` explicitly ends immediately when `ValueAnimator.areAnimatorsEnabled()` is false on API 26+. Android's animator duration scale affects animator delay/duration; zero disables them. Device animation scale, accessibility animation settings, and battery saver must therefore be recorded before comparing motion. Source constants alone do not prove elapsed wall time. [Telegram disable handling](https://github.com/DrKLO/Telegram/blob/f32ffeec763f0bdbf4bec25b52d654f77bff733d/TMessagesProj/src/main/java/me/vkryl/android/animator/FactorAnimator.java#L198-L217), [Android animator settings](<https://developer.android.com/reference/android/animation/ValueAnimator#getDurationScale()>), [enabled state](<https://developer.android.com/reference/android/animation/ValueAnimator#areAnimatorsEnabled()>).

## Comparison and next measurement

Keyboard Controller 1.21.9's `KeyboardStickyView` applies shared keyboard height directly to `translateY`, with interpolated optional offsets. It exposes no duration/easing prop. Its Android callback reads `animation.durationMillis` and dispatches height derived from current animated insets. The public controller API exposes focus, dismissal and input-mode operations, not a global system-IME curve setting. [Sticky view](https://github.com/kirillzyusko/react-native-keyboard-controller/blob/2068a7f7622a903444d5841c26eb4bc2cb235307/src/components/KeyboardStickyView/index.tsx#L11-L28), [direct transform](https://github.com/kirillzyusko/react-native-keyboard-controller/blob/2068a7f7622a903444d5841c26eb4bc2cb235307/src/components/KeyboardStickyView/index.tsx#L57-L65), [native duration](https://github.com/kirillzyusko/react-native-keyboard-controller/blob/2068a7f7622a903444d5841c26eb4bc2cb235307/android/src/main/java/com/reactnativekeyboardcontroller/listeners/KeyboardAnimationCallback.kt#L180-L195), [native movement](https://github.com/kirillzyusko/react-native-keyboard-controller/blob/2068a7f7622a903444d5841c26eb4bc2cb235307/android/src/main/java/com/reactnativekeyboardcontroller/listeners/KeyboardAnimationCallback.kt#L231-L291), [public API](https://github.com/kirillzyusko/react-native-keyboard-controller/blob/2068a7f7622a903444d5841c26eb4bc2cb235307/src/types/module.ts#L50-L131).

Recommendation (inference): keep the IME edge and composer on the same frame source. Learn Telegram's separation of system IME, app-owned panels, and shared geometry; evaluate its Bézier for app-owned panel transitions only. Do not add `withTiming(250)` or a spring to a height that already follows IME frames. Porting its hybrid maximum requires measuring composer-to-IME gap throughout opening and closing, because it can deliberately choose the app trajectory over the platform trajectory. A different normal-focus IME curve is possible through coordinated native IME control, with cancellation and end-state handling; it is not an existing `KeyboardStickyView` prop.

When the Android 16 test phone is available, compare our current build with its installed Telegram under the same IME, navigation mode, refresh rate, animator scale and animation-accessibility settings. Record opening and closing separately; distinguish cold-focus delay from travel duration. Track both IME top and composer bottom per frame; report time to 10/50/90/99%, maximum gap, end-of-animation jump, and long-frame stalls. A composer pixel trace alone cannot identify the system IME curve.

The parent investigation's historical 30 fps `composer-sticky.mp4` trace measured approximately 533 ms from 10–90% and 967 ms from 1–99%. These are historical composer-motion measurements supplied by the parent, not current native IME duration, a same-device Telegram comparison, or proof of an animation-scale multiplier. No phone verification was performed in this research.

## Follow-up phone observations, 2026-10-17

After USB recovery, an empty QA chat on Android 16 used the installed WeType IME and a 120 Hz display. Read-only global settings showed window/transition animation scales of 1.0 and no stored animator-duration override. The Keyboard Controller native event metadata reported 285 ms, while its will-show to did-show native timestamps spanned 1,360 ms in the baseline recording. The 30 fps composer detector saw 27 intermediate positions and no large jump or final keyboard overlap.

Two isolated application experiments did not materially change this: `translate-with-padding` reported a 1,274 ms native event span, and Android navigation `freezeOnBlur` with the original padding mode reported 1,224 ms. A no-screenrecord translation run still reported about 1,201 ms. These are individual diagnostic trials, not statistically qualified performance improvements. Translation mode was reverted. The event span includes application callback scheduling; it does not alone establish the IME window's travel duration or prove that list relayout caused the delay. A same-IME comparison with another application and native frame tracing remain needed before changing native IME control. No system animation preference or IME was changed.
