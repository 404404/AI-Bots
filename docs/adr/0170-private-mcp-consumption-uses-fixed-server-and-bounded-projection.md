# Private MCP consumption uses a fixed server and bounded projection

The application-defined `ProtectedMcp` Consumer reuses DSH 0.2.0-rc.1's exported `createMcpToolDefinition` adapter and its official `@modelcontextprotocol/client@2.0.0` dependency. Its Agent-scoped Registration is `mcp__private_status__authenticated_status`. The model-facing schema contains an account and three opaque field references. Native ToolRuntime and the existing approval record that original invocation. The application-defined `PrivateInputs.consume` owner checks the actual live Agent, PersonaBot creation identity, account, canonical configured Channel proof and current native Credentials grant before resolving values. There is no new credential store, UI or approval category.

Within the authorized callback, a fresh SDK Client connects to a fixed immutable Node program over private stdio. `initialize`, `tools/list` and `tools/call` are actual MCP exchanges; this is not a call to the existing protected CLI renamed as MCP. The selected original strings exist in the Host's private MCP arguments, not the outer model invocation or a nested Session Tool call. The native adapter receives only an application-produced bounded result after private execution finishes. It never sees the raw credential-bearing transport arguments, untrusted remote body, headers or errors.

The server supports one `authenticated_status` operation per process: one GET to the Owner-supplied private endpoint using the API key and secret. It forbids URL userinfo, non-HTTP(S) URLs, non-loopback plaintext HTTP, redirects and arbitrary command/header/environment/server selection. It discards response body and headers and reports only numeric HTTP status. The Host accepts only the exact matching status/text protocol result, rejecting additional metadata, content blocks, resources and structured fields before the native adapter's image persistence or Spill paths. Static failures contain no original SDK/server error or cause. HTTP 401/403 returns the same safe Web replacement/remote-authorization repair advice as the CLI consumer. Success describes HTTP status, not independent proof of third-party authentication; the controlled fixture verifies credentials separately.

This server is trusted Host code, not an arbitrary third-party server. Its program is an immutable module string passed to the exact Host Node interpreter, with a temporary working directory, no Agent-selected source or arguments, no secret in argv/environment and ignored stderr. The SDK merges selected ambient defaults even when `env` is supplied; this Provider explicitly overrides those names, retaining only Windows SystemRoot, and the child removes other environment entries before serving. SDK legacy negotiation deliberately avoids disposable auto-discovery siblings. There is no reconnect, resource/prompt registration, server instruction injection, general read/eval tool or model-controlled command in this connection.

The owning Fiber disposes the application Provider. Each use has a deadline and the scoped AbortSignal from `PrivateInputs`; abort, replacement, revocation and Host disposal kill its exact process and close its SDK transport. Cleanup retains and awaits the first close promise. The existing stop summary remains honest about completed remote effects and uncertainty. A failed or cancelled operation explicitly reports that a remote request may already have started and remote effects are unknown, preventing the model from equating cancellation with no execution. Structured logs identify discovery/start/completion/failure and duration without payloads. Exact Agent-local ToolDefinition identity qualifies the model-facing Registration; a matching MCP name alone is insufficient. The Host explicitly checks the four allowed parameter names before resolution: native schema declarations alone do not enforce rejection of additional arguments.

The protected Profile and Linux Execution World from ADR-0164 remain prerequisites. Arbitrary Agent Shell and ordinary configured MCP servers stay in their qualified Linux containers with authorized workspaces and no Host credential file, process namespace, environment or Docker socket. Ordinary MCP keeps its native Client Plugin; its server configuration cannot select or receive private grants. The new fixed Consumer does not qualify arbitrary stdio/HTTP MCP, Connectors, browsers or Host filesystem access. Trusted Owner, Host Plugins/interpreter, Docker daemon/image and fixed server remain outside the Agent threat boundary. A compromised trusted Host or server cannot be repaired by result masking.

Rejected alternatives are substituting plaintext into ordinary MCP tools, trusting arbitrary MCP output filtering, modifying the outer ToolExecution arguments after approval, and hiding a plaintext-schema registration beside a reference-schema tool. These expose credentials through server-controlled code, Session persistence, images, resource links, errors or general reads. Adding another secret input or approval product would duplicate existing authorities. This slice qualifies one fixed generic authenticated-status consumer; future consumer paths need their own operation and returned-data qualification.

Rollback removes this new registration and Provider without credential migration, while retaining the existing protected Profile and account-version enforcement. Never use that rollback to reopen the same credential-bearing Profile with an older unfenced binary. See the [runnable MCP guide](../dev/guides/private-input-mcp.md).
